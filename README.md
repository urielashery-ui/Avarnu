# עברנו

אתר שבו לקוח שעובר דירה ממלא את הפרטים שלו פעם אחת, ומקבל רשימה של כל הגופים שצריך לעדכן: משרד הפנים, חברת החשמל, תאגיד המים, ארנונה, גז, תקשורת, בנק, קופת חולים ועוד. לכל גוף יש קישור לאתר שלו ונוסח מוכן להעתקה.

האתר גם בודק אילו **הנחות** מגיעות ללקוח, לפי מה שסימן על משק הבית: ילדים, הורה יחיד, אזרח ותיק, נכות, מילואים, עולה חדש, הכנסה נמוכה ועוד. הוא בודק הנחות בארנונה, בחשמל ובמים, סבסוד מעון יום, זיכוי ממס ליישוב מוטב, ועוד דרכים לחסוך. לכל הנחה מופיע השיעור המרבי, מה להגיש, קישור, ונוסח מוכן לבקשה.

הלקוח בוחר אחת משתי אפשרויות:
- **"אעדכן בעצמי"**: הרשימה נשלחת אליו במייל.
- **"תעדכנו בשבילי"**: הפנייה מגיעה למסך הניהול עם משימה לכל גוף, ונציג מבצע את העדכונים.

## מה יש בתיקייה

| מה | איפה |
|---|---|
| הטופס (עיצוב, טקסטים, שלבים) | `src/app.html`, `src/app.js` |
| רשימת הגופים, הקישורים והנוסחים. קובץ אחד, משותף לדפדפן ולשרת | `src/catalog.js` |
| השרת: קבלת פניות, הצפנה, אבטחה | `server/index.js` |
| מסך הניהול | `server/admin.js` |
| חיבורים: מייל, Webhook, וחיבור לכל גוף | `server/connectors/` |
| בדיקות | `test/` |

`npm run build` בונה מאותו מקור שתי גרסאות:
- `public/`: האתר האמיתי.
- `dist/artifact.html`: דמו בקובץ אחד, שעובד בלי שרת.

## הרצה במחשב (לבדיקה)

צריך Node.js בגרסה 22.13 ומעלה.

```bash
npm install
npm start
```

פותחים בדפדפן את http://localhost:3000. מסך הניהול נמצא ב-http://localhost:3000/admin, והכניסה בפיתוח היא `admin` / `admin-dev-only`.

## העלאה לאוויר

### אפשרות 1: Render, Railway או Fly.io (הכי פשוט)
1. מעלים את התיקייה ל-GitHub.
2. יוצרים שירות חדש מה-repo. ה-Dockerfile מזוהה אוטומטית.
3. מוסיפים **דיסק קבוע (volume)** שמחובר ל-`/app/data`. בלי זה, הפניות נמחקות בכל עדכון.
4. מגדירים משתני סביבה לפי `.env.example`, לפחות את `DATA_KEY`, `ADMIN_USER`, `ADMIN_PASS` ו-`PUBLIC_URL`.
5. מחברים את הדומיין (למשל `avarnu.com`). ה-HTTPS מגיע אוטומטית.

### אפשרות 2: שרת משלכם (VPS)
```bash
cp .env.example .env        # ממלאים את הערכים
npm run keygen              # מדביקים את התוצאה ב-DATA_KEY
docker build -t movers .
docker run -d --name movers --env-file .env -p 3000:3000 -v movers-data:/app/data --restart unless-stopped movers
```
מול השרת שמים Nginx או Caddy עם HTTPS.

> **חשוב:** שומרים עותק של `DATA_KEY` במקום בטוח, למשל במנהל סיסמאות. בלי המפתח אי אפשר לפתוח את הפניות השמורות.

### גיבוי
כל המידע נמצא בקובץ אחד: `data/movers.db`. הוא מוצפן, ומגבים אותו פעם ביום.

## חיבורים (התממשקות)

### 1. מיילים
- **לעסק:** התראה על כל פנייה חדשה, עם קישור למסך הניהול. מוגדר ב-`NOTIFY_TO`. מטעמי פרטיות, במייל הזה אין פרטים אישיים.
- **ללקוח:** הרשימה המלאה עם הקישורים, בלי תעודת זהות.
- מגדירים `SMTP_URL`. אפשר להשתמש ב-Gmail (סיסמת אפליקציה), SendGrid, Brevo או כל שרת SMTP. בלי SMTP המיילים לא נשלחים, רק נרשמים בלוג.

### 2. CRM / Make / Zapier / n8n / Monday
מגדירים `WEBHOOK_URL`, ועל כל פנייה חדשה נשלח POST עם JSON:

```json
{
  "event": "lead.created",
  "ref": "MV-7K2QXA",
  "service": "concierge",
  "name": { "first": "נועה", "last": "לוי" },
  "phone": "050-1234567",
  "email": "noa@example.com",
  "moveDate": "2026-10-15",
  "newAddress": { "street": "הרצל", "number": "10", "apt": "4", "city": "פתח תקווה", "zip": "" },
  "oldAddress": { "street": "ילין 5", "apt": "", "city": "פתח תקווה" },
  "bodies": [{ "id": "moin", "title": "משרד הפנים (רשות האוכלוסין)", "auto": false }]
}
```

- תעודת הזהות **לא** נשלחת ב-Webhook.
- אם מגדירים `WEBHOOK_SECRET`, כל בקשה נחתמת בכותרת `X-Movers-Signature: sha256=...` (HMAC של גוף הבקשה). כך אפשר לוודא שהבקשה באמת הגיעה מהאתר.

### 3. חיבור לגופים (משרד הפנים, חברת החשמל וכו׳)
**המצב היום:** לאף אחד מהגופים אין API פתוח שמאפשר לגורם חיצוני לעדכן כתובת. לכן כל גוף מוגדר במצב **ידני**. כך זה עובד בפועל:
- הלקוח מקבל קישור ישיר לטופס של הגוף, ונוסח מוכן להדבקה.
- בשירות "תעדכנו בשבילי", הנציג רואה במסך הניהול משימה לכל גוף, מעדכן באתר של הגוף ומסמן "עודכן".
- גופים שמקבלים את הכתובת ממשרד הפנים (ביטוח לאומי, רשות המסים, משרד התחבורה) מסומנים "מתעדכן לבד".

**כשיהיה API** (למשל בהסכם עם ספק חשמל פרטי או עם תאגיד מים), מוסיפים לגוף פונקציית `submit` בקובץ `server/connectors/index.js`. יש שם דוגמה בהערה, ושום דבר אחר במערכת לא משתנה.

**ייפוי כוח:** כדי לפנות לגופים בשם הלקוח צריך ייפוי כוח חתום. הלקוח מסמן הסכמה בטופס, אבל את ייפוי הכוח עצמו צריך להחתים בנפרד, למשל בחתימה דיגיטלית.

### עדכון רשימת הגופים וההנחות
כל הגופים, ההנחות, הקישורים והנוסחים נמצאים בקובץ אחד: `src/catalog.js`.
- שיעורי ההנחה בארנונה נמצאים בטבלה `ARNONA`. הם לקוחים מתקנות ההסדרים במשק המדינה (הנחה מארנונה), התשנ״ג-1993, ומהמדריך של משרד הפנים.
- השיעורים מתעדכנים מדי פעם, ולכן כדאי לעבור על הטבלה פעם בשנה.
- אחרי כל שינוי בקובץ מריצים `npm run build` ומפעילים את השרת מחדש.

**פרטיות ההנחות:** מה שהלקוח סימן על משק הבית (נכות, קצבאות וכו׳) הוא מידע רגיש.
- הוא נשמר מוצפן, ורק מסך הניהול מציג אותו.
- הוא לא נשלח במייל לעסק ולא ב-Webhook. ב-Webhook נשלח רק מספר ההנחות.
- בשירות "תעדכנו בשבילי" כל הנחה הופכת למשימה של הנציג.

## מודל עסקי (מוכן, כבוי כרגע)

היום הכול בחינם. התשתית כבר בנויה, ומפעילים כל חלק במשתנה סביבה אחד, בלי לשנות קוד.

### 1. שותפים ממומנים (פרסום "קלאסי")
- במסך התוצאות יש מקום לעד 3 הצעות, אחרי הרשימה ולא לפניה. זה לא מפריע ללקוח לסיים את מה שבא לעשות.
- רק הצעות שקשורות למעבר: הובלות, ניקיון, ספק חשמל, אינטרנט, ביטוח דירה, צביעה, מנעולן.
- אפשר להתאים הצעה לעיר, לשוכרים או לבעלים, ולמשפחות עם ילדים.
- כל הצעה מסומנת **"ממומן"**, כמו שדורש חוק הגנת הצרכן. הקישורים מסומנים `rel="sponsored"`.
- בלי רשתות פרסום, בלי עוגיות ובלי מעקב אחרי אנשים, ולכן גם לא צריך באנר עוגיות.
- כל קליק עובר דרך `/go/<id>`. הוא נספר, ולקישור מתווסף UTM, כך שהשותף רואה כמה לקוחות הגיעו ממכם.
- להפעלה: מעתיקים את `config/sponsors.example.json` ל-`config/sponsors.json`, ממלאים, ומגדירים `ADS_ENABLED=true`. אם משנים את הקובץ בזמן שהשרת רץ, השינוי נכנס לתוקף תוך רגע.
- **אנחנו לא מעבירים לשותפים פרטים של לקוחות.** אם תרצו בעתיד למכור לידים, צריך הסכמה מפורשת ונפרדת מכל לקוח.

### 2. תשלום קטן על שליחה או טיפול
- מגדירים מחיר נפרד ל"תעדכנו בשבילי" (`PRICE_CONCIERGE`) ול"אעדכן בעצמי" (`PRICE_SELF`). אפשר להשאיר את העדכון העצמי בחינם.
- כשהתשלום פעיל:
  1. הפנייה נשמרת במצב "ממתינה לתשלום".
  2. הלקוח עובר לדף תשלום מאובטח של ספק הסליקה.
  3. רק אחרי אישור חתום מהספק נשלחים המיילים ונפתחות המשימות.
- פנייה שלא שולמה נמחקת אחרי 48 שעות.
- פרטי אשראי לא עוברים אצלנו בכלל.
- **ספקי סליקה מתאימים:** Grow (משולם), Cardcom, PayPlus, Tranzila. לכולם יש דף תשלום מאובטח, ורובם תומכים גם ב-Bit.
- כדי לחבר ספק, כותבים לו קובץ קטן ב-`server/payments/` עם שתי פונקציות: `createCheckout` ו-`verifyWebhook`. בקובץ `server/payments/index.js` יש הסבר.
- לבדיקה במחשב: `PAYMENTS_ENABLED=true PAYMENT_PROVIDER=mock PRICE_CONCIERGE=39`. זה פותח דף תשלום לדוגמה. בייצור הספק mock חסום.

### 3. רשימת תפוצה
- בשלב השליחה יש תיבה **לא מסומנת**: "אשמח לקבל מעברנו הצעות...".
- חוק התקשורת (סעיף 30א, "חוק הספאם") אוסר לשלוח דיוור שיווקי בלי הסכמה מראש. לכן שולחים הצעות רק למי שסימן.
- ההסכמה נשמרת, מופיעה בייצוא לאקסל, ונשלחת ב-Webhook (`marketingConsent`).

### 4. נתונים למכירת שותפויות
במסך `/admin/stats` יש:
- כמה פניות היו
- כמה ביקשו שירות מלא
- הערים המובילות
- ההנחות הנפוצות
- קליקים לכל שותף
- משפך הטופס: כמה אנשים נכנסו לכל שלב

המונים אנונימיים: בלי IP ובלי עוגיות. אלה בדיוק המספרים שחברת הובלות תרצה לראות לפני שהיא משלמת.

## פיילוט מובילים

הלקוח שעובר דירה ומבקש הצעות מחיר מקבל עד 3 מובילים שבדקנו, מהאזור שלו. כל מוביל מקבל את הפנייה במייל.

**הזרימה:**
1. **בטופס:** בשלב "הובלה" שואלים "כבר סגרתם מוביל?". מי שרוצה הצעות ממלא חדרים, קומות, מעלית ותוספות, ומסמן הסכמה מפורשת.
2. **בחירת מובילים:** עד 3 מובילים פעילים שמשרתים את העיר הישנה או החדשה (`*` = כל הארץ).
   - קודם מי שקיבל הכי מעט פניות השבוע, אחר כך לפי דירוג, ובשוויון באקראי.
   - כל מוביל מוגבל במכסה שבועית.
   - **מוביל שמשלם לא מקבל עדיפות.**
3. **הלקוח** רואה מיד למי נשלחה הבקשה, עם שמות וטלפונים. אותו דבר מופיע גם במייל שלו.
4. **המוביל** מקבל מייל ובו:
   - הפרטים (בלי תעודת זהות ובלי כתובת מלאה)
   - כפתור וואטסאפ ללקוח
   - קישור אישי לעדכון מצב: יצרתי קשר, נתתי הצעה, נסגר, לא נסגר. בלי סיסמה, והקישור בתוקף 45 יום.
5. **בקשת דירוג:** `REVIEW_DELAY_DAYS` ימים אחרי המעבר הלקוח מקבל מייל עם בקשה לדרג. הביקורת מתפרסמת רק אחרי אישור ב-`/admin/reviews`.
6. **`/movers`:** דף "מובילים מומלצים", עם דירוג רק אחרי `MIN_REVIEWS_TO_SHOW` ביקורות. אם יש מוביל משלם, מופיע גילוי נאות.
7. **`/movers/join`:** טופס הצטרפות. הבקשה נכנסת כמוביל לא פעיל.

**במסך הניהול (`/admin/movers`):**
- כל מוביל: כמה פניות קיבל, כמה אחוז הגיבו, זמן תגובה ממוצע, כמה נסגרו ודירוג.
- ערים שביקשו הובלה ואין בהן מוביל. שם כדאי לגייס את המובילים הבאים.
- כדי להפעיל מוביל חובה לסמן שבדקתם ביטוח ושהוא אישר את התנאים.

**להפעלה:** מוסיפים מובילים, ואז מגדירים `MOVERS_ENABLED=true`.
- טיוטת תנאי השותפות: `docs/mover-agreement-draft.md`. צריך בדיקה של עורך דין.
- רשימת הכנות להשקה: `docs/launch-checklist.md`.

## שפות: עברית, English, Русский, العربية

- **בורר שפה בראש הדף.** בעברית ובערבית הדף מימין לשמאל, באנגלית וברוסית משמאל לימין.
- **כתובות ישירות:** `/en`, `/ru`, `/ar`. טוב לפרסום ממוקד, למשל מודעה ברוסית שמובילה ל-`/ru`.
- **זיהוי אוטומטי:** רק לדפדפן ברוסית או בערבית. דפדפן באנגלית נשאר בעברית, כי הרבה ישראלים משתמשים בדפדפן באנגלית. הבחירה של המשתמש נשמרת.
- **הנוסחים לגופים נשארים בעברית:** גם כשממלאים בשפה אחרת, הנוסחים שמעתיקים לגופים ו"כל הפרטים במקום אחד" יוצאים בעברית, כי הם נשלחים לגופים בישראל. ללקוח מוצג הסבר על זה בשפה שלו.
- **ערים:** יש רשימה של 47 ערים בארבע השפות, כולל ערים ערביות מרכזיות. כתובת כמו "Хайфа" או "حيفا" נשמרת כ"חיפה", כדי שקישורים, התאמת מובילים והנתונים יעבדו נכון.
- **מותגים:** שמות החברות (בזק, מכבי וכו׳) מוצגים בשפת הלקוח.
- **מיילים ללקוח** (רשימה ובקשת דירוג), **דף הדירוג** ו**דף המובילים המומלצים** מוצגים בשפת הלקוח.
- **מסך הניהול, המייל לעסק ומה שמקבל המוביל נשארים בעברית.** המוביל ומסך הניהול מקבלים שורה "שפה מועדפת לשיחה".
- **`SUPPORT_LANGS`:** באילו שפות הנציגים מדברים. זה מוצג ללקוח לפני שהוא בוחר "תעדכנו בשבילי".
- **תרגומים:** נמצאים ב-`src/i18n/{he,en,ru,ar}.js`. הבדיקה `npm test` מוודאת שכל המפתחות קיימים בכל השפות ושהמשתנים ({n}, {city}) זהים. כדאי שדובר/ת רוסית ודובר/ת ערבית יעברו על התרגומים לפני ההשקה.
- **פרטי קשר בהצהרות:** ממלאים פעם אחת ב-`src/site-info.js`, והם מופיעים בכל השפות.

## נגישות
האתר נבנה לפי **ת״י 5568** (WCAG 2.1 AA):
- ניווט מלא במקלדת וקישור "דילוג לתוכן".
- תוויות והודעות שגיאה שמוקראות בקורא מסך, וסיכום שגיאות עם קישורים לשדות.
- כפתור "נגישות": הגדלת טקסט, ניגודיות גבוהה, הדגשת קישורים, גופן פשוט ועצירת תנועה.
- ניגודיות צבעים תקינה במצב בהיר וכהה, ואזורי לחיצה בגודל 44 פיקסלים לפחות.
- הצהרת נגישות ומדיניות פרטיות, בחלון שנפתח מהתחתית.

`npm run test:a11y` מריץ בדיקת axe-core אוטומטית על כל השלבים. כדי לבדוק את האתר החי:
`BASE_URL=https://your-site npm run test:a11y`

**לפני העלייה לאוויר צריך למלא** את החלקים המסומנים בצבע בהצהרת הנגישות: שם רכז/ת הנגישות, טלפון, מייל ותאריך. הם נמצאים ב-`src/app.html`. מומלץ גם בדיקה ידנית עם קורא מסך, למשל NVDA או VoiceOver, לפני ההשקה.

## פרטיות ואבטחה
- כל פנייה נשמרת **מוצפנת** (AES-256-GCM).
- תעודת הזהות מוסתרת במסך הניהול, וכל הצגה מלאה שלה נרשמת ביומן.
- הפניות נמחקות אוטומטית `RETENTION_DAYS` ימים אחרי תאריך המעבר. אפשר גם למחוק פנייה ידנית, למשל לפי בקשת לקוח.
- הגנות מובנות: הגבלת קצב שליחה, מלכודת לבוטים, CSP מחמיר, הגנת CSRF במסך הניהול, והגבלת גודל בקשה.
- **לפני השקה:**
  - למלא את מדיניות הפרטיות (שם העסק, אחראי פרטיות, מייל).
  - לבדוק מול עורך דין את החובות לפי חוק הגנת הפרטיות, כולל רישום מאגר אם נדרש.
  - לבדוק מול עורך דין את נוסח ייפוי הכוח.
